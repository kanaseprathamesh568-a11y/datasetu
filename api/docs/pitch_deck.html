Problem Statement Discovery & National Context Understanding of Problem · 25% Rubric
The "Data Graveyard" of Indian Public Portals
India publishes over 550,000 public resources across data.gov.in and state portals (Karnataka, Telangana, Maharashtra). Yet, less than 2% provide programmatic REST APIs. Valuable public records sit trapped in dirty spreadsheet dumps.
⚠️ The 4 Fatal Flaws of Indian Open Datasets
  • 1. Inconsistent Geographical Taxonomy:
    The same district is spelled five ways across files: "Bengaluru Urban", "Bangalore (U)", "Blr-U". Datasets fail to join across agriculture, health, and census records without LGD (Local Government Directory) normalization.
  • 2. Multi-Row Headers & Footnote Pollution:
    Indian government Excel files feature merged ministry titles in top rows and explanatory footnotes (*Provisional) at the bottom, breaking generic CSV parsers.
  • 3. Indian Numeral & Unit Chaos:
    Columns mixed with "in Lakhs", "₹ Crores", "Quintals", and non-standard comma placement like 12,34,567 that crash standard IEEE numeric parsers.
  • 4. Static Tombstones With Zero CDC:
    Datasets updated periodically force developers to re-download 200MB CSVs manually and rewrite parsing code from scratch.

System Architecture & Pipeline Mechanics Quality & Originality · 25% Rubric
The 4-Stage Data-to-API Engine
DataSetu serves as an autonomous compiler from raw tabular data to OpenAPI 3.1 specifications. By combining heuristic table sniffing, LGD entity normalization, DuckDB columnar indexing, and dynamic OpenAPI generation, it requires zero manual coding.
1. Smart Sniffer
  • Header Boundary Detection: Heuristically detects and trims preliminary ministry titles and footnotes by measuring data-type entropy across rows.
  • Encoding Resilient: Seamlessly auto-detects UTF-8 BOM, CP1252, and legacy Windows-874 encodings commonly found in state portal spreadsheets.
Heuristic Table Sniffer
2. Bharat Normalizer
  • LGD Entity Resolution: Uses Jaro-Winkler and Levenshtein token matching against India's official Local Government Directory to standardize 750+ districts.
  • Indian Numeral Engine: Converts "Lakhs", "Crores", and non-standard comma notations into IEEE 754 float columns with unit standardization.
LGD 750+ Districts Match
3. Dynamic FastAPI
  • DuckDB Columnar Core: Ingests cleaned data into in-memory DuckDB / Parquet for sub-5ms vectorized SQL queries, filtering, and aggregation.
  • Auto-Generated Routers: Synthesizes typed Pydantic models and parameterized FastAPI routes (?limit=, ?sort=, ?state=) with interactive Swagger UI.
OpenAPI 3.1 & Swagger UI
4. Auto SDKs & CDC
  • Client SDK Synthesis: Auto-emits typed Python (httpx) and JavaScript/TypeScript client libraries on the fly.
  • Change Data Capture: Scheduled cron worker checks source ETag / SHA-256; automatically migrates schema and logs version changelogs.
Python/JS SDKs + CDC
